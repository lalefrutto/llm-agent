# Memory Policy

## Что сохраняется в долгосрочную память
- Факты, явно сообщённые пользователем (предпочтения, контекст
  проекта, повторяющиеся задачи).
- Резюме завершённых задач (не полная история сообщений).
- Обратная связь пользователя об ответах агента (для evals/дообучения
  промптов).

## Что НИКОГДА не сохраняется
- Секреты: пароли, API-ключи, токены, номера карт/документов.
- Полный вывод code_exec, если он содержит переменные окружения.
- Сырые данные из sandbox после завершения сессии (sandbox эфемерный
  по определению, см. `docker/`).

## Срок хранения и обновление
- Извлечение фактов в Mem0 2.x только аддитивное (UPDATE/DELETE в
  конвейере нет): противоречащие факты хранятся рядом. Поэтому агент
  получает факты в хронологическом порядке с датой и правилом «более
  поздний факт отменяет ранний» (`agent/graph.py`, `_memory_block`).
- Экстрактор ограничен правилами `MEMORY_EXTRACTION_RULES`
  (`memory/memory_manager.py`): только факты, которые пользователь
  сообщает о себе; ответы на вопросы, расчёты и знания о мире не
  сохраняются (иначе в память попадали галлюцинации экстрактора).
- В Mem0 отправляется только реплика пользователя, не ответ агента:
  иначе в память попадают «факты» о самом ассистенте и его прошлые
  галлюцинации (наблюдалось вживую, см. `agent/graph.py`, `finalize`).
- План (не реализовано): раз в N сессий — консолидация: схожие факты
  объединяются, устаревшие с истёкшим TTL архивируются и исключаются
  из retrieval.

## Границы short-term vs long-term
- **Short-term** — буфер диалога текущего треда (LangGraph
  checkpointer), живёт в пределах сессии/треда, включает последние
  20 сообщений (rolling summary старой части — в планах). Контекст
  модели — 12k токенов (`config/ollama/hermes3-12k.Modelfile`).
- **Long-term** — Mem0-хранилище, переживает сессии, скоупится по
  `user_id` (и опционально `agent_id`/`session_id` для мультиагентных
  сценариев с несколькими ролями).
