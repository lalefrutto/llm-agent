# Skills — что это и зачем

**Skill** — это не инструмент (tool) и не системный промпт. Это папка с
файлом `SKILL.md` (плюс, опционально, вспомогательные скрипты/шаблоны),
которая описывает **процедурное знание**: как делать конкретный
повторяющийся тип задачи хорошо, с учётом накопленных «граблей». Агент
сам решает, когда подгрузить skill в контекст — по описанию
(`description`) в frontmatter, без участия человека в момент запроса.

## Отличие skill от tool и от system prompt

| | Tool | Skill | System prompt |
|---|---|---|---|
| Что это | Функция с сайд-эффектом (вызов API, код) | Инструкция + best practices для класса задач | Постоянные правила поведения агента |
| Когда грузится | Вызывается явно моделью | Подгружается по релевантности запроса | Всегда в контексте |
| Меняется часто? | Редко (стабильный интерфейс) | Часто — это «живой» операционный документ | Редко |
| Пример | `code_exec()` | «Как писать финансовый отчёт по шаблону компании» | «Никогда не выполняй код вне песочницы» |

## Как правильно создавать skill (чек-лист)

1. **Один skill = один класс задач.** Не смешивать «анализ данных» и
   «написание писем» в одном файле.
2. **Frontmatter с `name` и `description`** — по `description` агент
   решает, релевантен ли skill текущему запросу. Описание должно
   явно перечислять триггеры (какие формулировки запроса должны его
   активировать), а не быть общим.
3. **Инструкции — операционные, не декларативные.** Не «пиши хорошо»,
   а «сначала сделай X, проверь Y, затем сделай Z»; включай известные
   ошибки/грабли (gotchas), как в этом же проекте сделано для docx/pptx.
4. **Skill не должен дублировать SOUL.md/system prompt.** Ценности и
   границы — в identity/prompts, процедуры — в skills.
5. **Держать компактным.** Skill — это контекст, который расходует
   токены; выносить длинные референсы во вспомогательные файлы,
   которые грузятся только при необходимости.
6. **Версионировать и тестировать.** Skill — код в широком смысле:
   при обновлении прогонять `evals/` на задачах, которые этот skill
   должен закрывать (регрессионный тест поведения).

## Список созданных skills

- `data-analysis/` — анализ табличных данных и построение выводов.
- `web-research/` — методология многошагового веб-исследования с
  проверкой источников.
- `report-writing/` — структурирование итогового отчёта пользователю.
- `code-review/` — самопроверка кода перед выполнением в песочнице.
