# Data Analysis Skill

## Когда НЕ применять
Если вопрос про данные — это просто "покажи первые строки" без анализа,
skill не нужен, это обычный file_read.

## Порядок действий

1. **Инвентаризация.** Прежде чем считать метрики — прочитать схему
   (колонки, типы, диапазон дат, кол-во строк, NaN/пропуски). Никогда
   не считать метрику "с ходу" без этого шага — частая ошибка: делать
   выводы на данных с некорректным типом столбца (строка вместо даты).
2. **Проверка на выбросы/дубликаты** перед агрегацией — иначе среднее
   и суммы будут искажены.
3. **Считать в коде (`code_exec`), не в уме.** Даже "простую" сумму по
   12 строкам считать через pandas/скрипт, а не текстом — модель
   систематически ошибается в арифметике на реальных данных.
4. **Формулировать вывод в терминах данных, а не общих фраз.**
   Плохо: "продажи выросли". Хорошо: "продажи выросли на 14% м/м,
   рост объясняется категорией X (+32%), при этом категория Y упала
   на 8%".
5. **Явно указывать ограничения вывода**: размер выборки, период,
   пропущенные данные, коррелация vs причинность.

## Частые грабли (gotchas)
- Смешение временных зон в датах при сравнении периодов.
- Деление на ноль / NaN в проценте изменения при нулевой базе.
- "Survivorship bias" при анализе только успешных/оставшихся записей.
- Округление на промежуточных шагах, искажающее финальную сумму.

## Формат вывода
Таблица/список ключевых метрик → 2-3 предложения интерпретации →
явные оговорки об ограничениях.
